# Mishkenaz — Funktionale Vektoralgebra

**Stand:** 2026-10-07  
**Status:** Arbeitsmodell / keine mathematische Vollalgebra behauptet  
**Grundlage:** kanonische Vektorarchitektur V00 + V01–V42; detaillierte Kernsemantik aus dem reviewten Migrationsbestand, abgeglichen mit aktuellem `main`.

## 1. Grundbefund

Die 42 Vektoren sind funktional **nicht homogen**.

Sie bilden mindestens fünf Typen:

1. **Zustands-/Konfigurationsvektoren** — beschreiben eine Form oder Lage;
2. **Prozess-/Transformationsvektoren** — verändern einen Zustand oder Zusammenhang;
3. **Relations-/Topologievektoren** — strukturieren Unterschied, Bindung, Schwelle oder Kopplung;
4. **Erkenntnis-/Informationsvektoren** — Wahrnehmung, Spur, Rückschau, Übertragung, Modellbildung;
5. **Meta-Operatoren** — wirken auf bereits gebildete Strukturen oder Prozesse.

Daher ist „Vektoralgebra“ hier zunächst ein sprachtheoretischer Begriff:

> ein System typisierter semantischer Operationen und Kompositionsregeln.

Es wird **nicht** behauptet, dass die Vektoren einen mathematischen Vektorraum im linearen Sinn bilden.

## 3. V00 Avi

`Avi` gehört funktional **nicht** einfach in eine der fünf Klassen.

Es ist:

```
POTENZIAL VOR AUSGEFORMTER RICHTUNG
```

und damit eher ein **Ausgangsbereich möglicher Operationen** als selbst eine bestimmte Operation.

Wichtig:

```
Avi != algebraisches Null-Element
Avi != Identitätsoperator
Avi != Nichtwissen
Avi != Negation
```

Ob Avi später formal als spezielles neutrales oder ungerichtetes Element modelliert werden kann, bleibt offen.

## 4. Erste Kompositionsregeln

### Regel 1 — Komposition ist im Allgemeinen gerichtet

```
A-B != B-A
```

Beispiel:

```
Res-Ref-Log
```

„vom Verbleibenden her rückschauend Struktur bilden“

ist semantisch nicht dasselbe wie:

```
Log-Ref-Res
```

„eine Struktur rückbeziehen und als Residuum setzen“.

Die Reihenfolge trägt Prozesslogik.

### Regel 2 — Ta erhält Unterscheidbarkeit

`Ta` wirkt in Kompositionen als Differenzbedingung.

```
Ma + Ta
```

ergibt daher nicht bloß stärkere Bindung, sondern:

> Bindung unter Erhalt eines Gegenübers.

Daraus folgt die bekannte Struktur:

```
Ma'Ta'U
```

als Bindung bei anerkannter Differenz.

### Regel 3 — Integration ist nicht automatisch Löschung von Differenz

`-kora` führt zusammen. Daraus folgt nicht automatisch:

```
-kora(Ta) = 0
```

Integration kann Differenz erhalten oder aufheben; die konkrete Konstruktion muss dies ausdrücken.

Damit bleibt Kontrakosmologie grammatisch möglich.

### Regel 4 — Wechselwirkung ist nicht Integration

```
-reso != -kora
```

Zwei Systeme können gekoppelt sein, ohne zusammenzufallen.

Das macht:

```
Ma'Ta'U-reso
```

zu einem starken Kandidaten für:

> Wechselwirkung in erhaltener Verschiedenheit.

### Regel 5 — Ori ist nicht Identität

```
Ori(A) != A
```

sondern näherungsweise:

```
Ori(A, Geschichte) -> A'
```

mit:

```
A' ähnlich/referenziell verbunden mit A,
aber unter durch den Verlauf veränderten Bedingungen.
```

Ori ist damit ein **historienabhängiger Rekursionsoperator**.

### Regel 6 — Erkenntniskomposition bewahrt Stufen

```
Res -> Saha -> Ref -> Log -> Tra
```

darf nicht kollabieren zu:

```
Res = Wahrheit
```

Jede Stufe kann ausfallen oder fehlerhaft sein.

### Regel 7 — Resonanzaspekte liegen außerhalb der Vektoralgebra

`-om/-ath/-il` bewerten nicht die mathematisch-semantische Operation selbst, sondern markieren die wahrgenommene relationale Passung ihres Vollzugs.

Also:

```
Vektorkomposition + Resonanzaspekt
```

nicht:

```
Resonanzaspekt = Vektoroperation
```

## 5. Typisierte Komposition statt freier Verkettung

Nicht jede Folge von Vektoren ist automatisch sinnvoll.

Arbeitsmodell:

```
INPUT-TYP -> OPERATION -> OUTPUT-TYP
```

Beispiele:

```
SPUR -> Ref -> rückbezogene Spur
rückbezogene Spur -> Log -> Rekonstruktionsmodell
MODELL -> Tra -> übermitteltes Modell
SYSTEM A + SYSTEM B -> -reso -> gekoppelte Systeme
gekoppelte Systeme -> -kora -> integrierte Formation
```

Damit wird deutlich: Ein zukünftiges Formalmodell braucht **Typverträglichkeit**, nicht nur eine Liste erlaubter Silbenfolgen.

## 7. Der tiefere Befund

Die Oktaven ordnen die Vektoren kulturell und semantisch.

Die funktionale Algebra legt quer dazu eine zweite Ordnung:

```
OKTAVEN = historische/semantische Architektur
FUNKTIONSTYPEN = operative Architektur
```

Beide Ordnungen können gleichzeitig gelten.

Damit erhält Mishkenaz eine bemerkenswerte Eigenschaft: Ein Vektor besitzt nicht nur eine Bedeutung, sondern eine **Rolle im Aufbau von Prozessen und Aussagen**.

## 8. Verbindung zu Omnizedenz, Kontrakosmologie und AVI

Die Algebra setzt keine dieser Theorien voraus.

Sie erlaubt aber, deren Anforderungen sauber auszudrücken:

- **Omnizedenz:** Relationen, Geschichte, Pfadabhängigkeit, offene Fortsetzung;
- **Kontrakosmologie:** Kopplung ohne notwendige Integration;
- **AVI:** Referenz, Beobachtung, Modell, Provenienz und getrennte Welt-/Beobachterebenen.

Entscheidend bleibt:

> Mishkenaz muss auch die Negation oder Widerlegung dieser Modelle ausdrücken können.

Die funktionale Algebra ist daher Spracharchitektur, keine kodierte Metaphysik.

1. Für jeden Vektor Input-/Output-Typen bestimmen.
2. Zulässige und unzulässige Zweierkompositionen testen.
3. Prüfen, welche Kompositionen nicht-kommutativ sind.
4. Prüfen, ob es echte Neutral-, Invers- oder Absorptionsoperationen gibt — ohne sie vorauszusetzen.
5. `Ori` formal auf Pfadabhängigkeit testen.
6. `Ma'Ta'U-reso` und `-kora` gegeneinander als Kontrakosmologie-Test verwenden.
7. Erst danach entscheiden, ob „Algebra“ streng formalisiert werden kann.
